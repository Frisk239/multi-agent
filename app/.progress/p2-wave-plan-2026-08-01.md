## P2-2 · B4 运行时发现登录 shell fallback

**性质：探测健壮性。** 参照 Multica `server/internal/daemon/config.go:832` `resolveAgentsViaLoginShell`（`-ilc` 一次性解析，救回 fnm/nvm 装的 CLI）。本仓 `detect-path.ts:17-70` 只有 env 覆盖 + `which/where` 查找，非交互 PATH 里没有的 CLI 探测不到。

### Must
1. `resolveCmd` 失败后加登录 shell 兜底（POSIX：`$SHELL -ilc "command -v <candidate>"`，超时对齐既有 `detectVersionTimeout`；Windows 下跳过或降级 `cmd /c where`）
2. 兜底结果不缓存进 env，探测链保持幂等
3. 单测：PATH 遮蔽 + 登录 shell 命中 / 未命中 / 超时三条路径（mock execFile）

### Out
- 启动时全量 CLI 预探测（现按需探测，保持）
- 跨平台登录 shell 差异的完整矩阵（Windows 只做降级）

### 文件面
`server/src/runtime/detect-path.ts`(+test) · `server/src/runtime/registry.ts`（如探测入口需透传）

### 验收

## P2-4 · 运行时连接不上的自动改派（2026-08-01 人解禁 · 改设计）

**性质：自动兜底，防本地运行时连接不上。** 人已解禁「Deferred 默认强制改派」禁区，并拍板设计：**agent 显式配置 fallback + 任务级兜底**（不碰 issue.assignee）。

**改设计（不做 Multica fire_at 竞速）：**
- Multica 原版：评论触发时预置 deferred fallback 惰性任务 + `fire_at` 竞速（状态机增量大）
- 本仓改法：**不预置**。复用既有 auto-retry 基建（`failure-classify.ts` `AUTO_RETRY_FAILURE_REASONS` 含 `runtime_offline`；`auto-retry.ts` `insertRetryChild` 生成子 run）——**auto-retry 预算用尽仍失败（连接不上类）→ 生成改派子 run 给 fallback agent**（新列 `escalated_from_run_id` 追溯），原 run 终态注明「已自动改派给 X」，inbox/activity 通知
- 触发面（修正 2026-08-01 验收发现）：**连接不上类 = `runtime_offline`（预算用尽后改派）∪ CLI 无法启动（探测失败「CLI 未安装」/ `spawn … ENOENT`，直接改派不 gate attempt——这类不进 auto-retry）**；`exit 1` 等执行失败（CLI 跑了但任务报错）不改派（防误伤）；timeout/stale_heartbeat 等「慢/卡」类维持 auto-retry + 可观测，不改派
- **深度 1 防循环**：改派子 run 不再二次改派；fallback 也连不上 → 正常 failRun + 可观测
- 无 fallbackAgentId 的 agent → 行为不变（现 auto-retry + 可观测）

### Must
1. DB 迁移：`agents.fallback_agent_id`（nullable）+ `agent_runs.escalated_from_run_id`（nullable）
2. `auto-retry.ts` 预算用尽路径：`isAutoRetryableFailureReason(reason)` 且 reason=连接不上类 且 agent 有 fallback（存在/未归档）且 `escalated_from_run_id` 为空 → INSERT 改派子 run（agent_id/runtime 换 fallback，kind=issue，attempt 归零，squad/is_leader 清空），复用既有 INSERT...SELECT 子 run 模式
3. 原 run 终态 error 注明改派去向 + activity `run_escalated`（双 run payload）+ inbox 通知
4. 深度 1：`escalated_from_run_id` 非空 → 不再改派
5. shared schema：Agent 类型/Input 加 fallbackAgentId；web agent 编辑加「后备 agent」下拉（组件测试）
6. 单测：预算用尽+有 fallback → 改派子 run；无 fallback → 现状；非连接类失败不改派；深度 1；fallback 归档 → 不改派

### Out
- deferred 状态 / `fire_at` / 竞速（Multica 原版，人已同意改设计绕开）
- queued 超时未 claim 的自动改派（主观「慢」，维持可观测）
- 链式多级改派（深度 1 上限）
- claim 前「agent 无 runtime」路径的改派（若实现中发现现成处理则顺带，否则 Out）

### 文件面
`shared/src/schema.ts` · `server/src/db/schema.ts` + migration · `orchestration/auto-retry.ts`(+test) · `orchestration/run-worker.ts`（挂接）· `orchestration/activity-logger.ts`（如新 eventType）· `web/components/AgentForm*.tsx`（fallback 下拉）

### 验收
vitest（上 Must 6 组）· e2e：runtime 探测失败 + fallback 配置 → 出现改派子 run + activity 记录

## 排序理由

1. **P2-1 先行**：最小、纯前端、零风险，可独立演示，顺手收掉 GAP-07 尾巴。
2. **P2-2 次之**：后端小改，运行时发现健壮性，与 W4/W5（CI/契约）无耦合。
3. **P2-3 再**：wiki 超车项，中等成本，收益在多 project 场景（低频但真实）。
4. **P2-4 已解禁**（2026-08-01 人拍板）：agent 显式 fallback + 任务级兜底，复用 auto-retry 基建，触发面窄（仅 runtime_offline），深度 1 防循环。
