## P2-2 · B4 运行时发现登录 shell fallback

**性质：探测健壮性。** 参照 Multica `server/internal/daemon/config.go:832` `resolveAgentsViaLoginShell`（`-ilc` 一次性解析，救回 fnm/nvm 装的 CLI）。本仓 `detect-path.ts:17-70` 只有 env 覆盖 + `which/where` 查找，非交互 PATH 里没有的 CLI 探测不到。

### Must
1. `resolveCmd` 失败后加登录 shell 兜底（POSIX：`$SHELL -ilc "command -v <candidate>"`，超时对齐既有 `detectVersionTimeout`；Windows 下跳过或降级 `cmd /c where`）
2. 兜底结果不缓存进 env，探测链保持幂等
3. 单测：PATH 遮蔽 + 登录 shell 命中 / 未命中 / 超时三条路径（mock execFile）

### Out
- 启动时全量 CLI 预探测（现按需探测，保持）
- 跨平台登录 shell 差异的完整矩阵（Windows 只做降级）

### 文件面
`server/src/runtime/detect-path.ts`(+test) · `server/src/runtime/registry.ts`（如探测入口需透传）

### 验收
vitest 三路径 · e2e：模拟登录 shell 输出命中 → 探测成功

## P2-3 · B5 Wiki 跨项目索引（GAP-14）

**性质：wiki 超车项深化。** `wiki/query.ts:7` 注释「DS3：仅检索所选 wiki 根（不跨根）」；`wiki/store.ts:64-92` per-project root 解析。多 project 时 query 只能问当前根，沉淀在别的 project 的知识不可达。

### Must
1. query 管线支持**跨根检索**：请求侧加显式开关/参数（如 `roots: 'all' | string[]`），合并多个根的关键词匹配候选（Step 1），LLM 选页与合成答案不变
2. 合并候选按根标记来源，引用输出能区分页归属（沿用现有 `- [id=…]` cite 形状）
3. 默认行为不变（不跨根），开关显式开启——不破坏既有 DS3 语义
4. 单测：双根合并候选、根归属标记、默认不跨根回归

### Out
- 跨项目**索引**（增量建库/embedding 向量化）——query 时合并即可达，不建新存储
- Wiki 图谱 / 可视化

### 文件面
`server/src/wiki/query.ts`(+test) · `server/src/wiki/store.ts`（如根枚举需导出）· `web` 检索入口（可选开关，若 API 参数透传简单则顺手）

### 验收
vitest（双根候选合并 + 归属 + 默认回归）· e2e：两个 project 各建 1 页，跨根 query 命中另一根页面

## 排序理由

1. **P2-1 先行**：最小、纯前端、零风险，可独立演示，顺手收掉 GAP-07 尾巴。
2. **P2-2 次之**：后端小改，运行时发现健壮性，与 W4/W5（CI/契约）无耦合。
3. **P2-3 再**：wiki 超车项，中等成本，收益在多 project 场景（低频但真实）。
4. **P2-4 最后/或挂起**：半刻意 + 触及宪法边界，**默认不自动开**；要开需人点头（解禁「自动改派」才值得做全，只做 fire_at 惰性价值打折）。
